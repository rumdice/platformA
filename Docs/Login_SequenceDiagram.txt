  sequenceDiagram
      autonumber

      actor Client as 🎮 게임 클라이언트
      participant Auth as 🔐 Auth API
      participant Ticket as 🎟️ Ticketing API
      participant Worker as ⚙️ QueueWorker
      participant Match as ⚔️ Match API
      participant Game as 🎮 Game Server (TCP)
      participant Redis as 🟥 Redis
      participant DB as 🐬 MySQL DB

      Note over Client, DB: [ Phase 1 ] 로그인 및 인증

      Client->>Auth: 로그인 요청 (HTTP POST : auth/login)
      Auth->>DB: 유저 정보 검증
      DB-->>Auth: 유저 레코드 반환
      Auth->>Redis: Refresh Token 저장 (7일 TTL)
      Auth-->>Client: JWT 발급 (Access 15분 / Refresh 7일)

      Note over Client, Redis: [ Phase 2 ] 대기열 처리

      Client->>Ticket: 대기열 진입 요청 + Heartbeat갱신 (HTTP POST : queue/enter)
      Ticket->>Redis: 큐(Sorted Set)에 유저 등록
      Ticket-->>Client: 대기열 대기 티켓 응답

      alt SignalR 연결 성공시 (실시간 Push)
          Client->>Ticket: 대기열 통과 응답 수신 (SignalR : /hubs/queue)
          loop 1초 주기 (분산 락 적용 : SET NX)
              Worker->>Redis: Ghost 유저 정리(60초) / 상위 N명 Active 전환 (대기열에서 뺀다)
          end
          Worker-->>Client: Active 된 유저 Server push (event : QueueActivated) -> 게임서버 로그인
      else SignalR 실패 (Fallback 스마트 폴링)
          loop 대기열 순위 기반 응답시간 조절
              Client->>Ticket: 대기 순위 확인 + Heartbeat갱신 (HTTP GET : queue/status)
              Ticket-->>Client: 순위/상태(Active || wait)/NextPollDelay -> Active시 탈출 게임서버 진입
          end
      end

      Note over Client, Game: [ Phase 3 ] 게임 서버 진입

      Client->>Game: TCP 접속 + C_Login (JWT, RoomId = 1[광장])
      Game->>Redis: Active 키 검증 및 소비 (입장권 1회 회수)
      Game-->>Client: S_Login (성공 / 로비 입장)

      Note over Client, Game: [ Phase 4 ] 인게임 액션

       loop 광장 실시간 이동
          Client->>Game: C_Move (좌표 패킷)
          Game-->>Client: S_Move (룸 내 전체 브로드캐스트)
      end

      Note over Client, Match: 매칭 버튼 입력 → 매칭 요청 (상세 흐름은 별도 시퀀스 참조)
      Client->>Match: SignalR 연결 + 매칭 요청
      Match-->>Client: MatchFound (RoomId)
      Client->>Game: C_EnterRoom (RoomId)
      Game-->>Client: S_EnterRoom (배틀룸 입장)
