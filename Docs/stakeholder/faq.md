# 자주 묻는 질문 (FAQ)

## 시스템 용량

**Q. 최대 몇 명까지 동시에 이용할 수 있나요?**

대기열에는 최대 **10,000명**이 동시에 대기할 수 있습니다.  
실제 게임 서버의 동시 접속 수는 서버 인스턴스 수에 따라 조정됩니다.

---

**Q. 매칭에 얼마나 걸리나요?**

시스템은 **0.2초(200ms)마다** 대기 중인 플레이어를 매칭합니다.  
이론적으로 상대방이 대기 중이라면 수백 밀리초 내에 매칭됩니다.  
단, 동시 접속자가 적을 경우 최대 **2분**까지 대기할 수 있으며, 2분 초과 시 매칭이 자동 취소됩니다.

---

**Q. 대기열 순서는 공정한가요?**

네. 먼저 대기열에 진입한 순서대로 처리됩니다. (FIFO 방식)  
새로 들어온 플레이어가 오래 기다린 플레이어보다 먼저 매칭되는 일은 없습니다.

---

## 접속 및 보안

**Q. 동시에 여러 기기에서 로그인할 수 있나요?**

**게임 서버 접속은 하나의 기기에서만 가능합니다.**  
동일 계정으로 두 번째 게임 서버 접속을 시도하면 자동으로 거부됩니다.  
(로그인 및 대기열 API는 다중 기기에서 사용할 수 있습니다.)

---

**Q. 접속이 갑자기 끊기면 어떻게 되나요?**

- **게임 서버에서 접속이 끊긴 경우**: 게임 방에서 자동으로 퇴장 처리됩니다. 분산 잠금(중복 접속 방지)도 자동 해제됩니다.
- **대기열 중 앱이 꺼진 경우**: 5분 이내 재접속 후 상태를 확인하면 됩니다. 5분 초과 시 대기열에서 자동으로 제거됩니다.

---

**Q. 비밀번호는 어떻게 보호되나요?**

비밀번호는 절대 원문으로 저장되지 않습니다. **BCrypt** 알고리즘으로 단방향 암호화(해싱)되어 저장됩니다.  
관리자도 원래 비밀번호를 알 수 없습니다.

---

**Q. 로그인 토큰이 탈취되면 어떻게 되나요?**

Access Token(로그인 확인증)은 발급 후 **15분**이 지나면 자동으로 만료됩니다.  
Refresh Token(재발급 키)은 서버에서 관리하며, 의심스러운 활동 감지 시 서버 측에서 강제 무효화할 수 있습니다.  
또한 Refresh Token을 사용할 때마다 새 토큰으로 교체됩니다 (Token Rotation).

---

## 데이터

**Q. 어떤 데이터가 저장되나요?**

| 데이터 | 저장 위치 | 보존 기간 |
|--------|---------|---------|
| 계정 정보 (ID, 비밀번호 해시) | MariaDB | 영구 |
| 게임 매치 기록 | MariaDB | 영구 |
| 대기열 상태 | Redis | 임시 (TTL 기반) |
| 로그인 토큰 | Redis | 최대 7일 |

---

**Q. 데이터는 어디에 저장되나요?**

- **영구 데이터**: MariaDB(MySQL 호환) 데이터베이스에 저장됩니다.
- **임시 데이터** (대기열, 세션): Redis(인메모리 캐시)에 저장되며 일정 시간 후 자동 삭제됩니다.

---

## 운영

**Q. 서비스 점검 시간이 있나요?**

현재 계획된 정기 점검은 없습니다.  
배포 시에는 Blue-Green 또는 Rolling Update 방식으로 무중단 업데이트를 목표로 합니다.

---

**Q. 장애 발생 시 어떻게 알 수 있나요?**

각 서비스는 `/healthz`(생존 확인)와 `/readyz`(준비 상태 확인) 엔드포인트를 제공합니다.  
모니터링 시스템에서 이를 주기적으로 확인하여 장애를 감지합니다.
