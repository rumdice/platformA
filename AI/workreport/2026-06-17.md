## 앞으로의 계획

### 방향 전환: SDLC → 수익화 게임 개발

SDLC 인프라 완성 이후 다음 개발 단계는 수익화를 목표로 하는 게임 개발이다.
공통 인프라(Platform)와 게임 서버 로직(GameServer)을 분리하여 병행 발전시킨다.

### 게임서버 로드맵 (단순 → 복잡 순서)

| 단계 | 장르 | 주요 기술 과제 |
|------|------|-------------|
| 1단계 | 캐주얼 PvP (턴제 1:1) | GameRoom 턴 관리, 게임 결과 DB 저장, MMR 연동 |
| 2단계 | 전략 / 카드 게임 | 복잡한 상태 관리, 덱/핸드 시스템, 비동기 타임아웃 |
| 3단계 | FPS (실시간) | 물리 예측 보정, 딜레이 컴펜세이션, 고주파 패킷 최적화 |

**제외**: 대규모 MMORPG (1인/소규모 팀에 부적합)

### 플랫폼 로드맵 (게임서버와 병행)

| 기능 | 우선순위 | 이유 |
|------|---------|------|
| 플레이어 레이팅/MMR (ELO) | 🔴 높음 | 매칭 품질 + 수익화 동기 부여 핵심 |
| 리더보드 (Redis Sorted Set) | 🟡 중간 | 재방문율 향상 |
| 결제/인앱 구매 API | 🟡 중간 | 수익화 직접 경로 |
| 어드민 API | 🟢 낮음 | 운영 도구 |
| 게임 결과/전적 DB 스키마 | 🔴 높음 | 모든 게임 기능의 기반 |

### 즉시 다음 단계 (결정 필요)

1. **첫 번째 캐주얼 PvP 게임 종목 결정** — 구체적인 게임 규칙이 있어야 Game.Server 설계 가능
   - 예시: 오목, Connect-4, 틱택토 계열 (단순하지만 완전한 매칭→게임→결과 파이프라인 검증 가능)
2. **Platform 선행 작업 결정** — 레이팅/MMR과 게임 결과 DB 스키마를 먼저 설계할지 여부

### SDLC 잔여 항목 (reactive — 필요 시만 처리)

- n8n end-to-end 실시간 검증 (실제 CI 실패 발생 시 자연스럽게 확인)
- `sdlc-python-test.yml`에서 `.github/tests/` 경로 포함 여부 확인
