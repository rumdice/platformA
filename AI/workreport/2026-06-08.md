### 1. AI_SDLC Phase 3 운영 안정화 (PR #78, 스프린트 #49)

**배경**: Phase 3(PostgreSQL dual-write) 구축 완료 후 실제 운영 과정에서 발생하는 문제를 선제적으로 완화하기 위한 안정화 작업.

- **`AI/sprints/` 구조 도입** — SPRINT.md에 모든 내용을 쌓는 방식을 폐기하고 스프린트별 독립 파일 관리 체계 도입 (sprint-NNN.md). SPRINT.md는 인덱스/요약 역할로 점진 전환하여 append-only 충돌 표면 축소.
- **`check_sdlc_consistency.py` 신규** — PostgreSQL `sdlc.ai_jobs` 레코드와 task JSON 파일을 비교하여 상태 불일치를 탐지하는 정합성 검사 스크립트. `--strict` 모드에서 critical 불일치(DB 누락·gate 불일치)만 exit 1로 차단.
- **`db_write.py` 실패 로그 추가** — DB dual-write 실패 시 `AI/logs/db-write-failures/YYYY-MM-DD.log`에 기록하여 실패를 묵살 대신 가시화.
- **`session-start.sh` 훅 업데이트** — 세션 시작 시 DB write 실패 로그와 AI/sprints/ 파일을 자동으로 요약 출력.
- **운영 정책 문서 3종 작성**: `ai-sdlc-auto-fix-policy.md`, `ai-sdlc-append-only-conflict-policy.md`, `ai-sdlc-db-migration-roadmap.md`.
  - 특히 migration roadmap은 Phase A(dual-write) → Phase B(DB 우선) → Phase C(DB 단독) 전환 기준을 명문화.

### 2. DB primary 전환 Phase B (PR #79, 스프린트 #50)

**배경**: Phase B 전환 조건을 검사한 결과 `db_write.py`의 컬럼명 버그(`sprint_number` → `sprint`)로 Sprint #44~#49 DB write가 전부 실패한 것을 발견. 버그 수정과 함께 backfill 및 게이트 DB primary 전환까지 일괄 처리.

- **`db_write.py` 버그 수정** — `INSERT INTO sdlc.ai_jobs (sprint_number, ...)` → `(sprint, ...)`로 수정. NOT NULL 컬럼 4개(`test_generated`, `review_completed`, `adr_required`, `retry_count`) 누락도 동시 수정. cp949 터미널 em dash 인코딩 오류(`—` → `-`)도 함께 수정.
- **sprint 카운터 수정** — `/plan` SKILL.md의 sprint 번호 산출 방식을 `ls | wc -l` (파일 수 기반, 동일 번호 파일 2개 시 오산)에서 `grep -o '[0-9]*' | sort -n | tail -1` (max 번호 기반)으로 수정.
- **DB backfill** — `migrate_tasks_to_postgres.py --apply`로 Sprint #44~#49 7개 INSERT + 24개 UPDATE. `backfill_model_runs.py` 신규 작성 후 12개 `ai_model_runs` 레코드 INSERT.
- **`/pr` 게이트 검사 DB primary 전환** — 검사 3~7(test_generated, review_completed, impact, requirement, adr_required)을 grep 파일 기반에서 DB SELECT primary + 파일 fallback 구조로 전환. `--action get-gates` DB 조회 결과를 실제 검사에서 사용하도록 수정.
- **Phase B 선언** — `check_sdlc_consistency.py --strict` exit 0 확인 후 `ai-sdlc-db-migration-roadmap.md`에 Phase B 진행 중으로 업데이트.
