## E2E 테스트 반복 실패 원인 분석

> 사용자 요청: 왜 E2E 테스트가 반복 실패했고 비용이 많이 들었는지

### 원인 1 — 잘못된 진단 순서 (가장 큰 비용 낭비)

초기 진단이 **`HttpListener` 바인딩 주소**(`http://+:7779/` → `http://localhost:7779/`)에 집중됐고, 이것만 수정하면 해결될 거라 판단. 실제 문제는 `ServiceManager.cs`의 헬스체크 방식이었는데 수정 전 검증을 E2E 전체 실행으로 반복하면서 매 시도마다 90~180초 + 빌드 시간을 소모.

**개선 방향**: 서비스 단독 실행 + `curl http://localhost:7779/healthz` 확인 → 1분 이내 진단 가능했음.

### 원인 2 — `_ = Task.Run(...)` 예외 무음 처리

`HttpListener.Start()` 실패 예외가 `Task.Run` 내부에서 발생해도 `_ =`로 결과를 버려 로그에 전혀 남지 않음. `[Gomoku HealthCheck] Listening on ...` 출력 후 7779가 실제로 응답하지 않아 원인 파악이 어려웠음.

**개선 방향**: 앞으로 `Task.Run` 내 `try-catch`에서 실패 로그 + 프로세스 종료 신호를 남겨야 함.

### 원인 3 — .msCoverageSourceRootsMapping 파일 잠금 반복

E2E 실행이 중간에 실패하면서 이전 테스트 프로세스가 커버리지 파일을 잠근 채 남음. 이후 `dotnet build`/`dotnet test` 시도마다 "오류 N개"가 뜨고 재시도 낭비.

**개선 방향**: E2E 실패 시 자동으로 `.msCoverageSourceRootsMapping_*` 파일 삭제 후 재시도.

### 원인 4 — KillByPort와 실제 프로세스 포트 불일치

`ServiceManager.KillByPort`가 `HealthUrl` 포트(7779)를 기준으로 종료하는데, Gomoku의 실제 TCP 포트는 7778. 이로 인해 이전 실행에서 Gomoku가 종료되지 않고 남아 다음 시작 시 7778 충돌. 이 문제를 인지하지 못한 채 `Program.cs`만 수정하고 E2E를 재실행하는 사이클이 반복됨.

## 오늘 작업 피드백 및 개선점

### 1. E2E 디버깅 비용 과다 소모 — 단위 검증 없이 E2E 전체 반복

**잘된 점**: 결국 `ServiceManager.cs`의 `TcpPort` 메커니즘이라는 근본 원인을 찾아 1줄로 해결함.

**개선하면 좋을 점**: E2E 실패 시 "해당 서비스만 단독 기동 + curl 헬스체크 확인" 절차를 먼저 수행했다면 1~2회 시도로 끝날 진단이 4~5회 E2E 전체 실행으로 늘어났음. 다음에는 개별 서비스 검증 → 원인 확정 → E2E 1회 순서를 지킬 것.

### 2. Task.Run 예외 무음 — 로그 없는 실패는 디버깅 블랙홀

**잘된 점**: `_ = Task.Run(...)` 패턴이 문제임을 인지했고 이후 다른 서비스에서 같은 패턴을 쓰지 않도록 교훈을 남김.

**개선하면 좋을 점**: `Task.Run` 내부 예외는 반드시 `Console.Error.WriteLine` 또는 Logger로 출력 + 프로세스 종료 신호를 남겨야 함. 현재 Game.Gomoku의 HttpListener 실패는 여전히 무음이므로 다음 스프린트에서 보완 필요.

### 3. 오늘 SDLC 흐름은 적절히 운영됨

**잘된 점**: Sprint #77(Rate Limit 전환), #78(테스트 보강), #79(E2E 수정)을 /plan → /done → /pr 흐름으로 체계적으로 처리. 특히 Sprint #78 테스트 보강은 `rl:*` 키 필터 + `try/finally` 복원 패턴을 일관되게 적용.

**개선하면 좋을 점**: E2E 스킬(`/e2e`)을 먼저 구현한 뒤 E2E 실행에 나섰다면, 스킬 내에서 단계별 검증(서비스 단독 헬스체크 → E2E 실행)을 구조화할 수 있었을 것.

### 4. /e2e 스킬 — 시나리오 9 헬스체크도 동일한 HTTP 방식

**잘된 점**: 시나리오 10은 ServiceManager 수정으로 안정화됨.

**개선하면 좋을 점**: /e2e 스킬의 시나리오 9 구간에서도 Game.Gomoku 헬스체크를 `http://localhost:7779/healthz`(HTTP)로 확인하는 코드가 있음. 이 부분도 TCP 체크(`powershell Test-NetConnection 7778`)로 변경이 필요함.
