### 2. 오목 Failover 개선 4종 — main 직접 작업

E2E 점검에서 발견된 엣지케이스 4종을 main 브랜치에 직접 구현. 커밋/push는 사용자 직접 수행.

**Item 1 — LobbyHub 명시적 로그아웃**
- `LobbyHub.Logout()` SignalR 메서드 추가: `_presence.Unregister(userId)` + `Context.Abort()` 로 명시적 세션 종료
- 기존에 클라이언트가 연결을 강제 끊거나 세션 만료까지 대기해야 했던 구조 개선

**Item 3 — 로비 disconnect 시 매칭 자동 취소**
- `LobbyHub.OnDisconnectedAsync` 에 Matching.API `DELETE /api/gamematch/CancelMatch` 자동 호출 추가
- JWT는 WebSocket `?access_token=` QueryString에서 추출하여 Authorization 헤더로 전달
- 매칭 대기 중 튕긴 유저의 좀비 큐 항목이 disconnect 즉시 제거됨

**Item 4a — MatchRecord Method B (게임 서버 입장 확인 방식)**
- `RecordMatchStartAsync`: `Status = InProgress` → `Status = Pending` (매칭 성사 직후는 아직 게임 미시작)
- `NotifyMatchStartedAsync(roomId)` 신규 추가: 게임 서버에서 2인 입장 확인 시 `Pending → InProgress`, `StartedAt` 기록
- `AbandonStaleMatchesAsync()` 신규 추가: Pending 레코드 중 10분 초과 시 자동 `Cancelled` (5분 주기 백그라운드 실행)
- `POST /api/gamematch/start` 엔드포인트 추가 (내부 서버 간 통신, 인증 불필요)
- `GomokuRoom.StartGame()`에서 `ReportMatchStartAsync()` fire-and-forget 호출

**Item 4b — WaitingPlayers 상태 disconnect 시 잔류 플레이어 알림**
- `HandleDisconnect` WaitingPlayers 분기에서 `GomokuRoomManager.Remove()` 전 `Broadcast(SGameOver { WinnerId=0, Reason=Disconnect, LobbyUrl })`추가
- 이전에는 잔류 플레이어가 상대방 퇴장 사실을 알지 못해 무한 대기 가능성 있었음

## 오늘 작업 피드백 및 개선점

### 1. 테스트 인프라 설계 접근

**잘된 점**: `TestableGomokuRoom(Broadcast override) + FakeGomokuSession(GomokuSession 상속)` 조합으로 TCP 소켓 없이 게임 오케스트레이션 레이어를 완전히 격리해 테스트. Moq나 추가 패키지 없이 C# 상속만으로 해결한 것이 깔끔함.

**개선하면 좋을 점**: CS1628(out 파라미터 람다 캡처 금지) 오류를 테스트 작성 후 발견해 수정이 필요했음. 작성 전 `room.Push()` 안에서 out 파라미터를 사용하지 못한다는 제약을 미리 인지했다면 첫 번째 빌드에 통과 가능했음.

### 2. 기존 구현 신뢰성 검증

**잘된 점**: 15개 테스트 전부 최초 실행에서 통과 — GomokuRoom의 기존 HandlePlaceStone, HandleDisconnect, FinishGame 가드 로직이 처음부터 올바르게 구현되어 있었음을 공식 확인.

**개선하면 좋을 점**: 신규 기능 추가 시 테스트를 코드와 동시에 작성하는 TDD 방식으로 전환하면 "나중에 검증 추가" 단계를 별도로 진행하지 않아도 됨.

### 3. 테스트 범위 선정

**잘된 점**: 무승부(보드 가득) 케이스를 Reflection으로 `_board` 필드에 224개 선행 채워 마지막 한 수만 HandlePlaceStone으로 두는 방식으로 처리 — E2E로는 재현 불가능한 경계 케이스를 단위 테스트에서 정확히 커버.

**개선하면 좋을 점**: 턴 타임아웃(StartGame 내 Task.Run 루프) 경로는 실제 타이머 대기가 필요해 이번 테스트에서 제외됨. `FakeTimer` 또는 시간 주입 패턴 도입 시 타임아웃 경로도 단위 테스트 가능.

### 4. E2E + 단위 테스트 역할 분담 명확화

**잘된 점**: E2E 시나리오 10(1000명 + Failover C)로 통합 경로 회귀를 확인하고, 단위 테스트로 거부/가드/무승부 등 E2E에서 자연 발생하지 않는 경계 케이스를 보완 — 두 레이어가 역할을 명확히 분담.

**개선하면 좋을 점**: 현재 E2E 시나리오는 정상 게임 완주와 Failover만 검증. 의도적으로 잘못된 순서의 돌 놓기나 동시 패킷 등 비정상 입력 시나리오를 E2E 레벨에서도 일부 추가하면 계층 간 커버리지 격차를 더 좁힐 수 있음.
