## 주요 작업 내용

### 1. AI_SDLC Phase 3 데이터 흐름 안정화 (PR #72, Sprint #43, L)

Phase 3(PostgreSQL 기반 SDLC 모니터링)의 데이터 흐름에서 발생하던 안정성 문제를 해결했다.

- `ai_failures` 테이블 중복 삽입 방지 — ON CONFLICT DO NOTHING 처리
- task JSON → PostgreSQL DB 이전 스크립트 작성 및 실행 (`migrate_tasks_to_postgres.py`)
- risk:HIGH 분류 — `PlatformA.Library/` 경로 및 DB 스키마 관련 변경 포함

### 2. 워크플로 완전 자동화 기반 구축 (PR #73, Sprint #44, L)

사람 개입 없이 plan~pr 전체 파이프라인을 한 번에 실행하는 `/workflow` 오케스트레이터를 도입했다.

- `.claude/skills/workflow/SKILL.md` 신규: plan → requirement → impact → start → 코딩 → test-gen → done → review → pr 순서 자동 체이닝
- `/done`, `/pr` 등 각 스킬의 사람 확인 요구 지점을 자동 계속 처리로 전환
- 스킬 차단 요인(gate 미통과, ADR 미생성 등) 전체 사전 진단 후 자동 우회 또는 명확한 중단 메시지 출력

### 3. Phase3 자동화 완성 (PR #74, Sprint #45, L)

CI 실패를 외부에서 감지하여 자동 수정 루프를 완성했다.

- GitHub Actions `repository_dispatch` → n8n → `/qa-failure` 자동 실행 파이프라인 구성
- `.github/workflows/auto-fix.yml` 신규: CI 실패 타입별 자동 수정 트리거
- `.github/workflows/plan-file-trigger.yml` 신규: `.claude/plan/` 파일 push → `/workflow` 자동 실행
- cost-log duration_sec/consume_tokens/cache_tokens 역산 인프라 구축 (`count_tokens.py`)

### 4. ai_model_runs 연동 (PR #75, Sprint #46, M)

`/pr` 스킬 완료 시 토큰 사용량을 PostgreSQL `sdlc.ai_model_runs`에 자동 기록하도록 연동했다.

- `.github/scripts/insert_model_run.py` 신규: `count_tokens.py` 결과 + task JSON → INSERT
- psycopg2 연결 실패(로컬 PostgreSQL 미실행) 시 경고 후 계속 진행 — `|| true` 안전 처리
- `.claude/skills/pr/SKILL.md` 4.2단계 추가: cost-log 기록 완료 후 `insert_model_run.py` 호출
- cost-log.md 병행 유지 — DB 연결 실패 시에도 파일 기반 비용 로그는 항상 기록됨

### 5. LLM 라우터 (PR #76, Sprint #47, M)

task의 위험도(`impact.risk`)를 읽어 적절한 Claude 모델을 자동 선택하는 라우터를 도입했다.

- `.github/scripts/get_task_risk.py` 신규: task JSON의 `impact.risk` → 모델명 매핑 출력
  - LOW → claude-haiku-4-5-20251001
  - MEDIUM → claude-sonnet-4-6 (기본값)
  - HIGH → claude-opus-4-8
- `.claude/skills/workflow/SKILL.md` 3.5단계 추가: `/impact` 완료 후 `get_task_risk.py` 호출 → `--model` 플래그 결정
- `.github/workflows/auto-fix.yml`: failure_type 기반 모델 선택 (FORMAT→Haiku, BUILD/TEST→Sonnet)
- `.github/workflows/plan-file-trigger.yml`: 계획 파일 헤더 `risk:` 힌트 파싱 → 기본 모델 결정

### 6. PostgreSQL primary 전환 (PR #77, Sprint #48, L)

task JSON 파일을 secondary로 강등하고 PostgreSQL을 SDLC 상태의 진실원(source of truth)으로 격상했다.

- `.github/scripts/db_write.py` 신규: `upsert-job`, `insert-step`, `get-gates` 3개 액션 지원
  - 모든 실패는 stderr 경고 + exit 0 — SDLC 흐름 차단 없음
- 7개 스킬 dual-write 적용: plan/start/done/pr/test-gen/review/impact
  - 각 스킬 핵심 동작 직후 `db_write.py || true` 호출 추가
- `/pr` 게이트 검사: grep 기반 → DB SELECT 전환 (파일 fallback 유지)
- 기존 45개 task JSON → PostgreSQL 이전 완료 (`migrate_tasks_to_postgres.py --apply`)
