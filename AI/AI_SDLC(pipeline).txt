작업 단계를 나눈다. 각 단계는 순차적으로 진행된다. (작성중)

0. USER_PLAN
기능 : 유저가 요구사항을 제출하거나 생성해낸다.
- 사용자(사람)이 어떤 모드에서던 LLM과 대화하여 어떠한 요구사항을 입력하고 구현을 위한 계획을 설립한다.(.md)
- 또는 유저가 다른곳의 AI Agent 등을 이용하여 어떤 계획을 만들어와서 .md 형태의 명세서로 제출한다.
- 현재 이 프로젝트의 경우 플렌모드에서 계획을 수립하거나 단순히 사용자가 요구 사항을 입력하면 계획을 짜주고, 브랜치를 계획에 맞게 생성하고 있다. 이 부분에 대한 수정이 필요하다. (REQUIREMENT_ANALYSIS 단계에서 진행)


1. REQUIREMENT_ANALYSIS
기능 : 0. USER_PLAN 단계에서 유저가 제출한 요구사항 계획(.md)을 분석한다.
- 요구사항을 분석하고 검토하여 오류 및 누락이 있는지 체크하고 있다면 질문한다.
- 요구사항의 분석 및 검토가 완료되면 사용자가 제출한 .md 계획 문서를 우선 사용자 글로벌 클로드 설정 C:\Users\rumdi\.claude\plans 경로에
저장한다. (향후 DB 저장으로 전환한다)
- 저장 포멧은 YYYY-mm-dd_TaskNumber_계획 추론 제목.md ex) 2026-05-14_001_RemoveGeneratorLib.md
- 단일 사용자,혹은 여러 사용자가 동일한날에 동시에 다양한 계획을 동시에 제출할 수 있음을 염두해 두고 위와 같이 제목을 작성한다.
→ /requirement 스킬로 구현됨 (2026-05-21, 스프린트 #22)

2. DESIGN_REVIEW
기능 : 요구단계분석이 끝났다면 코드의 설계 방향을 제시한다.

3. IMPACT_ANALYSIS
기능 : 코드의 설계 방향대로 코드 수정시 수정대상의 파일/모듈 들을 파악하고 위험도,영향도를 평가한다.
→ /impact 스킬로 구현됨 (2026-05-21, 스프린트 #22)

4. CODE_FIX
기능 : 실제로 코드를 수정한다.

5. TEST_CASE_GENERATION
기능 : 테스트 코드를 작성한다.

6. BUILD_TEST
빌드/테스트를 실행한다.

7. QA_FAILURE_ANALYSIS
실패 원인을 분석하고 재시도 여부를 판단한다

8. PR_SUMMARY
배포를 준비한다.
