작업 단계를 나눈다. 각 단계는 순차적으로 진행된다. (작성중)

0. USER_PLAN
기능 : 유저가 요구사항을 제출하거나 생성해낸다.
제출 경로는 아래 세 가지 중 하나이다:

  경로 A — Plan mode (Claude Code 기본)
  - 사용자가 Claude Code plan mode에 진입하여 LLM과 대화하며 계획을 수립한다.
  - plan mode는 ~/.claude/plans/ 에 임시 파일을 생성한다 (이력 없음, 매번 덮어써짐).
  - 사용자가 계획을 승인(ExitPlanMode)하면 stage 0 완료.

  경로 B — 외부 파일 제출 (외부 Agent, 기획서 등)
  - 외부에서 작성한 계획 파일을 .claude/plan/ 디렉토리에 저장한다.
  - 파일명은 자유롭게 지정 (예: temp_plan.md, feature-xyz.md).
  - /requirement 실행 시 이 디렉토리를 1순위로 탐색한다.
  - 처리 완료된 파일은 .claude/plan/processed/ 로 자동 이동된다.

  경로 C — 직접 입력
  - /requirement 요구사항 텍스트 형식으로 직접 입력한다.


1. REQUIREMENT_ANALYSIS
기능 : 0. USER_PLAN 단계의 계획을 분석하고 영구 명세 파일을 생성한다.
→ /requirement 스킬로 구현됨 (2026-05-21, 스프린트 #22 / 개선)

소스 탐지 우선순위:
  1순위: .claude/plan/*.md       — 외부 제출 파일
  2순위: ~/.claude/plans/        — plan mode 임시 파일 (동적 탐지, 고정명 불참조)
  3순위: /requirement [텍스트]   — 직접 입력

처리:
- 요구사항을 분석하고 오류/누락이 있으면 질문한다.
- 분석 완료 후 영구 명세 파일 생성: C:\Users\rumdi\.claude\plans\YYYY-MM-DD_NNN_PlanName.md
  ex) 2026-05-21_001_FixRedisBug.md  (이력 보존됨)
- NNN은 당일 생성 파일 수 기반으로 자동 증가 (다수 계획 동시 제출 지원).
- 명세 완료 후 /plan {PlanName} 으로 브랜치 생성 → 이후 단계 진행.

2. DESIGN_REVIEW
기능 : 요구단계분석이 끝났다면 코드의 설계 방향을 제시한다.
→ /requirement 스킬 5단계에 내장됨 (2026-05-21, 스프린트 #22 개선)
   - 기존 ADR 목록과 대조하여 충돌 여부 검토
   - 신규 설계 결정 필요 시 /adr 스킬로 연계
   - 별도 스킬 불필요 (요구사항 분석과 동일 맥락에서 수행)

3. IMPACT_ANALYSIS
기능 : 코드의 설계 방향대로 코드 수정시 수정대상의 파일/모듈 들을 파악하고 위험도,영향도를 평가한다.
→ /impact 스킬로 구현됨 (2026-05-21, 스프린트 #22 개선)
   - /plan 완료 보고에 다음 단계로 명시 (미실행 방지)
   - 코드 수정 전(사전): 명세 파일 "영향 범위" 섹션 기반 분석
   - 코드 수정 후(사후): git diff 기반 분석

4. CODE_FIX
기능 : 실제로 코드를 수정한다.

5. TEST_CASE_GENERATION
기능 : 테스트 코드를 작성한다.

6. BUILD_TEST
빌드/테스트를 실행한다.

7. QA_FAILURE_ANALYSIS
실패 원인을 분석하고 재시도 여부를 판단한다

8. PR_SUMMARY
배포를 준비한다.
