# ADR 생성

## 컨텍스트
- 현재 ADR 목록: !`ls AI/adr/ 2>/dev/null | sort || echo "(없음)"`
- 오늘 날짜: !`date +%Y-%m-%d`

## 사용자 입력
$ARGUMENTS

---

## 수행 순서

### 사전 검사

`$ARGUMENTS`가 비어 있으면 다음 사용법을 출력하고 **중단**한다:

```
사용법: /adr <결정 주제 (한글 또는 영문)>

예시:
  /adr MySQL Connection Pool 크기 결정
  /adr Matching API 인증 방식 선택
  /adr Rate Limiting 전략
  /adr AWS Secrets Manager 도입 여부
```

---

### Step 1: 다음 ADR 번호 계산

"현재 ADR 목록"에서 `NNN-*.md` 패턴 파일의 숫자 중 최대값을 찾는다.
다음 번호 = 최대값 + 1, 3자리 0-패딩 (예: `005`).
목록이 비어 있으면 번호 = `001`.

---

### Step 2: 파일명 생성

`$ARGUMENTS`(주제)를 소문자 kebab-case 영문으로 변환하여 파일명을 만든다:
- 한글 → 간결한 영문 요약 (예: "MySQL 연결 풀 크기 결정" → `mysql-connection-pool-size`)
- 공백·특수문자 → 하이픈 (`-`)
- 최대 45자

최종 파일명: `AI/adr/{NNN}-{kebab-title}.md`

---

### Step 3: 중복 확인

"현재 ADR 목록"에서 주제가 유사한 ADR이 이미 존재하는지 확인한다.
유사한 것이 있으면 알리고 계속할지 묻는다:

```
⚠️  유사한 ADR이 이미 존재할 수 있습니다:
    {파일명}
    계속 새 ADR을 생성하시겠습니까?
```

---

### Step 4: ADR 파일 생성

`$ARGUMENTS`와 프로젝트 컨텍스트(PlatformA — .NET 게임 백엔드)를 반영하여
아래 템플릿으로 `AI/adr/{NNN}-{kebab-title}.md` 파일을 생성한다.
초안 내용을 최대한 구체적으로 채운다 (빈 항목 최소화):

```markdown
# ADR-{NNN}: {원본 주제}

## 상태: 초안

## 날짜: {오늘 날짜}

---

## 맥락

{어떤 문제 또는 설계 결정이 필요한지 서술. 기술 부채, 요구사항, 보안 등 배경 포함.}

---

## 결정

**{선택한 접근 방식 한 줄 요약}**

{결정 내용 상세 설명. 구체적인 설정값, 적용 범위 포함.}

---

## 대안과 기각 이유

| 대안 | 기각 이유 |
|------|---------|
| {대안 1} | {이유} |
| {대안 2} | {이유} |

---

## 결과 및 트레이드오프

**이득:**
- {이점 1}
- {이점 2}

**비용 / 제약:**
- {단점 1}
- {단점 2}

---

## 변경 방법

이 결정을 변경하려면:
1. 새 ADR 작성 (`AI/adr/NNN-제목.md`)
2. 사용자 승인 후 진행
3. 이 ADR 상태를 `대체됨 (→ ADR-NNN)`으로 업데이트
```

---

### Step 5: 완료 보고

```
ADR 생성 완료
  파일:  AI/adr/{NNN}-{kebab-title}.md
  상태:  초안

초안을 검토하고 내용을 보완해 주세요:
  - 맥락: 왜 이 결정이 필요한가
  - 결정: 무엇을 선택했는가
  - 대안: 왜 다른 방법을 기각했는가

완료 후 상태를 '초안' → '확정'으로 변경하고 /done 으로 커밋하세요.
```

---

## ADR 포맷 규칙 (참조)

기존 ADR 패턴 (`AI/adr/001~007-*.md`) 기준:
- 상태값: `초안` / `확정` / `대체됨 (→ ADR-NNN)` / `폐기됨`
- 날짜: `YYYY-MM-DD` 형식
- 파일명: 소문자 kebab-case, 번호 3자리 0-패딩
- 변경 방법 섹션은 항상 마지막에 포함
