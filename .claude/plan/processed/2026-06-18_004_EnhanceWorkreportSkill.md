소스: /plan 작업 설명 (Sprint #68 DB job)

## 요구사항 요약

workreport 스킬에 두 가지 섹션을 추가한다:
1. 각 프로젝트의 완성도를 체크리스트 형식으로 평가하는 섹션
2. 오늘 작업의 피드백과 개선하면 좋을 점을 1~5가지로 정리하는 섹션

## 상세 요구사항

### 1. 프로젝트 완성도 평가 섹션

- 대상 프로젝트: Auth.API, Ticketing.API, Matching.API, Game.Server, Utils.API, Library.Game, Library (공통)
- 각 프로젝트에 대해 아래 항목을 체크리스트 형식으로 평가한다:
  - **빌드/테스트**: 빌드 통과 여부, 테스트 존재 여부 및 통과율
  - **API 문서**: `/doc-writer api-guide` 동기화 여부 (API 프로젝트만)
  - **헬스체크**: `/healthz`, `/readyz` 엔드포인트 구현 여부 (API 프로젝트만)
  - **Docker**: Dockerfile 존재 여부
  - **핵심 기능**: Sprint 이력 기반 주요 기능 구현 완료 여부 (간략 서술)
- 각 프로젝트별 완성도 점수(%)는 LLM이 판단하여 기재한다

### 2. 오늘 작업 피드백 및 개선점 섹션

- 오늘 머지된 PR과 완료된 sprint를 바탕으로 1~5가지 피드백을 작성한다
- 각 피드백 항목은 아래 형식을 따른다:
  - **잘된 점**: 이번 작업에서 효과적이었던 것
  - **개선하면 좋을 점**: 다음 번에 더 잘할 수 있는 부분
- 기술적 개선점과 프로세스 개선점을 모두 포함한다
- LLM이 오늘의 코드 변경과 작업 흐름을 분석하여 자체적으로 생성한다

## 제약 및 주의사항

- C# 코드 변경 없음 → 빌드/테스트는 영향 없음
- 완성도 평가 기준은 LLM이 직접 판단해야 하므로 외부 도구 의존 없이 자체 분석 방식을 사용한다
- sprint 파일 및 ADR은 읽기 전용 참조 (수정 없음)
- 프로젝트 완성도 평가는 실제 코드 탐색 + sprint 이력 기반이어야 한다
  (단순 체크리스트 반복이 아닌 실제 파일 존재 여부 확인)
